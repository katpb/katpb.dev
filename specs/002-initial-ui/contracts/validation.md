# Validation Contract: R2 — Initial UI

**Branch**: `002-initial-ui` | **Date**: 2026-10-02

Applies to `specs/002-initial-ui/contracts/site-ui.md` and
`specs/002-initial-ui/contracts/theme.md`. Acceptance procedures are in
`specs/002-initial-ui/quickstart.md`. No acceptance claim is made during planning.

## Existing command and build guarantees

Preserve the existing scripts and pinned toolchain. `npm run verify` must fail on formatting,
Astro/TypeScript diagnostics at the existing warning threshold, production build, Playwright/axe,
Node workflow, or reproducibility failure. No new dependency or replacement validation stack.
Default development port 4321 remains strict with an actionable conflict message; preview/tests
use 4322 without reusing an unrelated server. Stop preview before browser tests need that port.

`npm run build` produces complete local static pages/resources and removes stale output. Interrupted
commands remain recoverable by rerunning them. Builds/checks do not mutate tracked source, canonical
SVG, package manifest, or lockfile. Preserve checkout-path-with-spaces compatibility.

`npm run test:reproducible` retains R1's sorted normalized-path and per-file SHA-256 comparison.
Unchanged builds have the same generated files and substantive content. Identified volatile
filesystem timestamps, ownership, and permissions may differ; no arbitrary generated bytes are
excluded. R2 requires no new comparison or volatile-content allowlist. Browser preference cannot
affect build output, and source must not depend on timestamps, randomness, or external content.

After initial dependency and pinned-browser acquisition, development, build, and full verification
must run with the network disconnected. Runtime resource checks allow only local origin resources;
outbound approved profile links do not need to be followed during offline testing. Do not add
external URL probes to `verify`. Content review separately establishes approved destinations.

routes; retain the R1 foundation checks, replacing only the obsolete operational-status content
assertion. Add focused scenarios within existing tooling rather than introduce another suite.

Use one combined Playwright init script per storage setup/fault scenario to avoid undefined ordering
between scripts. Retention tests reuse retained origin state in a later context; do not assume a
fresh empty context represents a later visit. Initial-flash tests inspect first rendered state and
built initializer ordering; settled screenshots alone cannot certify pre-paint behavior.

On every primary route, block or abort stylesheet requests before direct navigation and verify
readable document structure/content, reachability of all four primary navigation destinations,
and current-page identification through HTML text such as “Current” or “Current page” plus
`aria-current="page"`. This must survive without CSS or generated content; identification must
not depend exclusively on CSS, color, background, borders, icons, pseudo-elements, or generated
content. Record results in `specs/002-initial-ui/checklists/acceptance.md` when it is created.

Do not claim synthetic smaller viewport, device scale factor, or CSS zoom as true browser zoom.
Viewport automation supplements, not replaces, manual actual 200% zoom.

## Final manual review

Record all four primary pages in current native Chrome and Safari on macOS on Apple Silicon.
Playwright WebKit is not native Safari acceptance. Record actual macOS/browser versions, reviewer,
date, revision, viewport, zoom, effective theme/mode, preferences, results, and evidence links.

- Keyboard: full traversal, skip link, every nav/action/theme option, visible unobscured focus,
  logical order, current/focus distinction, no traps or hidden/duplicate identity stops.
- VoiceOver with Safari: named Home identity, no separate decorative SVG announcement, headings,
  landmarks, current page, theme label/selected mode, list/card semantics, and reading order.
- Responsive: 320 CSS pixels, representative mobile/desktop/intermediate widths, actual 200%
  browser zoom, text growth, breakpoint crossing, rail fit/non-fit and reachable bottom, one scroll
  area. Mobile intro/profile placement and nav/control wrapping remain correct.
- Visual/preferences: contrast on all actual surfaces and states, light/dark, reduced motion,
  forced colors/high contrast where available, no-JS/blocked enhancement readability, missing media
  and destinations, long content, and stable canonical mark dimensions.
- Cold initial rendering: opposite-system saved Light/Dark, direct entry to every route, throttled
  filmstrip and first-render evidence; no incorrect-theme flash or reveal layout shift.
- Styles disabled in native Chrome and Safari on every primary route: readable structure/content,
  reachable Home/Writing/Projects/About destinations, and surviving current-page HTML text plus
  `aria-current="page"` without CSS or generated-content dependence; record final results in
  `specs/002-initial-ui/checklists/acceptance.md` when it is created.

R1's earlier VoiceOver deferral does not constitute approval to skip R2 screen-reader review.
Record unavailable/unperformed acceptance as incomplete and surface it; do not invent results.

## Repeatable performance gate

Use production preview, current Chrome Stable Incognito, 360×800 CSS pixels, Fast 4G and 4× CPU
slowdown. Record the actual preset values (R1 recorded 20ms latency, 4Mbps down, 3Mbps up), hardware,
macOS/Chrome/Node/npm versions, revision/build identity, observation interval, and cache policy.
Do not silently substitute materially different conditions.

For each route independently, perform five unchanged cold runs. Start each in System with cleared
site data/cache. Open Performance Live Metrics, navigate, perform the same pointer/keyboard skip
actions, choose Light→Dark→System using the theme control, and scroll to the footer. Finish after
the same recorded observation interval following the last interaction. Scroll exposes layout
shifts but is not itself an INP interaction. Capture native LCP/local INP/CLS, interaction evidence,
and screenshots or traces. A missing INP measurement is incomplete, not zero.

Sort each route's five values per metric; the fourth is nearest-rank p75. All four routes must
pass LCP ≤2500ms, local INP ≤200ms, CLS ≤0.1; never pool runs across pages. Keep all 20 raw runs.
Use Chrome's local metric, not R1's historical raw Event Timing maximum approximation, and do not
substitute Lighthouse TBT. No runtime vitals/analytics library is added. Opposite-system saved-theme
flash checks are supplementary, not changes to the canonical System-start performance protocol.

## Real-reviewer outcomes

Use at least five first-time representative reviewers from at least two intended audience groups.
Cover mobile and desktop; record the first-exposure viewport and avoid rehearsing the five-second
test. Record counts, denominator, and anonymized response summaries, not unnecessary personal data.

| Criterion | Required evidence                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SC-001    | Five-second Home exposure: ≥80% identify engineer/technology leader and one focus area.                                                                                                                                                                                                                                                                                                                                                             |
| SC-002    | ≥90% locate Writing/Projects/About and reach chosen destination within one desktop/two mobile actions.                                                                                                                                                                                                                                                                                                                                              |
| SC-003    | ≥80% identify Writing as notebook within the same four-page brand.                                                                                                                                                                                                                                                                                                                                                                                  |
| SC-011    | Use the exact five-point/four-statement rubric in [spec.md SC-011](../spec.md#measurable-outcomes) and [quickstart.md Section 8](../quickstart.md#sc-011-reviewer-scoring): combined-positive means ≥3 positive answers and no negatives; ≥80% combined-positive reviewers with the required count rounded upward, and negative responses from fewer than half of all reviewers for each quality; retain anonymized raw responses and denominators. |

With five reviewers, ≥80% means at least 4/5 and ≥90% means 5/5. Automated screenshots/content
checks cannot certify these qualitative criteria. Keep reviewer responses/evidence local; no site
data-collection feature is introduced.
